# Goals

Serve these goals with every change to this repo. Check each change against them.

1. Autonomy. Take a feature from agreed intent to working code without pulling the user back into details.
2. Level discipline. Work only at the current level. Move down a level only when the current one passes its review and the user approves it. Set lower-level questions aside for the level that owns them.
3. Production-ready features, not prototypes. Settle invariants and design decisions before the build, or mark them as non-goals.
4. MVP first. Build the smallest framework that carries its own build, then apply it to a product feature. Don't refine a level beyond what the next level needs.
5. Fix instructions, not cases. When a gate gives wrong or unstable results, change the skill so it converges; don't judge case by case.

## Decide or ask

- `skills/references/decisions.md` sets who makes each decision. Make and record the work's decisions, then report them; ask about the user's.
- Before acting on anything from the user that could change the project, play back what you understood and wait for confirmation. Ask one question at a time, with a recommended answer and enough detail to answer it.
- Never guess. Look up a fact, ask a decision, ask a reading, and put to the user anything you can't settle one of those ways.
- Fixes that aren't decisions need no approval; every decision needs approval. A fix is not a decision only when it restores the document to something already agreed and cites it. Never ask to commit or push agreed work, or to take the agreed next step.
